# Implementation plans

Ground the plan in current files and requirements. Capture goal, non-goals, affected components, dependency order, verification, and unresolved decisions. Use concrete file references and acceptance conditions; include code only when it resolves real ambiguity.

Scale the plan to the work. Avoid minute-by-minute steps, complete code duplicated into documentation, mandatory failing tests for trivial changes, and per-step commits. Use the user's location or .tmp/plans/TASK.md.

Check requirement coverage and incompatible assumptions once. Ask only about a missing consequential decision. A plan-only request ends with the plan. An implementation request continues in this session without a second ceremony; use agents only if authorized and available. No mandatory superpowers or Claude execution dependency. Planning does not authorize Git publishing.
